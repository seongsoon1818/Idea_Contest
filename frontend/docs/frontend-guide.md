# 한성픽 프론트 구조와 화면별 기능 안내

대상: v1.16.75 · 2026-10-16 · 기획/디자인 담당자와 백엔드 담당자가 함께 읽는 안내입니다.

## 1. 이 폴더를 받으면 무엇을 할 수 있나요?

현재 배포한 프론트 화면을 로컬에서 실행하고 수정할 수 있습니다. HTML은 화면의 뼈대, CSS는 색·폰트·여백·반응형 배치, JavaScript는 필터·저장·팝업·이동을 담당합니다. React 프로젝트가 아니며 npm build 단계도 없습니다. **`dist/` 안의 파일이 직접 편집하는 소스**입니다.

화면 동작은 구현했지만 실제 회원 계정·학교 데이터·AI 서버와 연결한 서비스는 아닙니다. 로그인 버튼이 있다는 이유로 인증 서버가 구현된 것은 아닙니다. 운영 전 해야 할 작업은 [백엔드 연동 전달서](backend-handoff-2026-10-16.md)에 있습니다.

## 2. 실행과 확인

저장소 최상위에서 다음을 실행합니다.

```bash
cd frontend/dist
python3 -m http.server 8080
```

브라우저에서 `http://localhost:8080/`을 엽니다. Windows에서 `python3` 명령이 없다면 설치된 Python에 맞게 `py -m http.server 8080`을 사용할 수 있습니다. 모듈을 불러오므로 파일을 더블클릭해 `file://`로 열지 않습니다. 포트가 이미 사용 중이면 다른 포트를 선택합니다.

Node.js로 자동 검사를 실행할 때는 별도 터미널에서 다음을 실행합니다.

```bash
cd frontend
npm run check
```

현재 전달본은 Node.js 24에서 검사했습니다. npm 패키지 설치 없이 실행됩니다. 검사는 실제 모바일/PC 브라우저 테스트를 대신하지 않습니다.

## 4. 화면 지도

이 앱은 한 HTML에서 주소 뒤 `#`에 따라 화면을 바꿉니다. 서버의 개별 페이지 경로와 다릅니다.

| 주소의 해시 | 사용자에게 보이는 화면 | 주요 기능 |
|---|---|---|
| `#recommend` | 맞춤 추천 홈 | 학년별 배너, 맞춤 PICK/MY PICK/마감 PICK 요약, 공지 PICK/비교과 PICK, 필터·결과 |
| `#notices` | 공지사항 | 공지 분류, 검색·정렬·모집중 필터, 목록·상세 |
| `#programs` | 비교과 프로그램 | 비교과 분류, 동일한 탐색 도구, 공개 정보 중심 상세 |
| `#saved` | MY PICK | **북마크된 항목만** 표시. 추천 필터는 저장 항목과 현재 추천 대상의 교집합 |
| `#profile` | MY PAGE | 내 정보, 소셜 계정 연결, 비밀번호 변경, 추천정보 다시 설정·회원 탈퇴 UI |
| `#login` / `#signup` | 로그인 / 회원가입 | 입력 규칙·오류 표시·화면 전환. 실제 요청은 미연결 |

온보딩·내 정보 2단계 입력·트랙 선택·게시물 상세·이미지 확대·비교·확인창은 공통 `dialog`를 사용합니다. 브라우저 Back/Forward와 팝업 복원을 위한 상태가 `history.state.hsuUI`에 들어갑니다. 이 이력은 서버 인증/저장 데이터가 아닙니다.

## 5. 주요 동작은 어디서 찾나요?

대부분 `dist/app.js` 안의 함수 이름으로 검색하면 됩니다. 코드를 기능별 파일로 나누려면 아래 단위가 분리 기준입니다. 이번 전달본은 기존 동작 보존을 위해 파일 구조를 재작성하지 않았습니다.

| 기능 | 검색할 함수/키워드 | 주의점 |
|---|---|---|
| 화면·탭 전환 | `render`, `renderNav`, `navigate`, `route` | 모바일 하단바와 PC 사이드바가 같은 화면 상태 사용 |
| 카테고리·검색·정렬 | `filterHtml`, `fitCategoryRows`, `getList`, `applySort`, `toggleSearch` | 모바일은 두 줄 배치를 시도하되 글자 확대 시 읽기 위해 줄바꿈 허용 |
| 카드·숫자·빈 상태 | `card`, `cardFacts`, `resultHtml`, `stats` | 개수와 목록의 필터 조건을 함께 변경 |
| 개인 추천 | `recommendedItems`, `matchProfile`, `recommendationReason` | 지금은 로컬 규칙. 실제 AI 요청 없음 |
| 북마크 | `toggleSave`, `persist`, `saved` | 지금은 localStorage. 계정별 서버 저장으로 교체 필요 |
| MY PICK | `renderSaved`, `getList` | 미저장 항목이 섞이지 않게 유지 |
| 상세·원문·이미지 | `detail`, `source`, `imageViewer`, `noticeImages` | 이미지 표시와 OCR/AI 요약은 별도 기능 |
| 비교 | `toggleCompare`, `comparison`, `completeComparison`, `renderTray` | 2~3개 선택. 완료 시 비교 선택 해제·북마크 유지 |
| 내 정보 | `startProfile`, `profileStep`, `captureProfileDraft` | 미완성 입력을 즉시 기존 프로필에 덮어쓰지 않음 |
| 트랙 팝업 | `openTrackPicker`, `renderTrackPicker`, `trackOptionsForSlot` | 첫 화면은 검색/소속 선택부터. 중복 트랙과 학년별 필수 규칙 확인 |
| MY PAGE·미니 MY | `profilePage`, `renderMiniMy`, `accountDialog` | 이름 표시와 로그인 여부를 혼동하지 않기 |
| 온보딩 | `showOnboarding`, `finishOnboarding` | 첫 방문·다시 보기·로그인 전/후 복귀 경로 확인 |
| 뒤로가기·팝업 | `openModal`, `backInApp`, `mobileSnapshot`, `restoreMobile` | 팝업 안에서 새 팝업을 여는 경우 이력·포커스도 함께 확인 |
| 데이터/날짜/오프라인 | `refreshVisibleData`, `refreshDateState`, `updateConnectivity` | 오프라인 안내는 있지만 오프라인 설치 앱이나 서버 동기화 기능은 없음 |

## 6. 디자인을 수정할 때의 공통 규칙

- 공통 폰트는 자체 호스팅 Pretendard입니다. 자간 기준은 `-0.5px`이며 로고·아이콘 등 별도 요소의 예외 규칙은 CSS에서 확인합니다.
- 모바일/PC를 별도 앱으로 복제하지 않고 같은 데이터·화면 렌더러를 사용합니다. `app.js`의 모바일 분기 기준은 800px입니다. CSS에는 개별 요소를 위한 다른 미디어쿼리도 있으므로 함께 확인합니다.
- 선택 색은 화면 맥락에 따라 다릅니다. 공지/비교과 탐색과 추천 상태를 색 하나로 일괄 치환하지 않습니다. `recommend-home`, `saved-page`, `browse-page`, `saved-recommended` 클래스가 맥락을 구분합니다.
- 카테고리는 폰트·내부 여백·높이·아이콘 간격을 공통으로 보고, 모바일 가로 배율은 `fitCategoryRows`와 함께 확인합니다.
- 북마크는 저장 시 아이콘 안에 색을 채우는 방식입니다. 아이콘 바깥 배경을 일괄 추가하지 않습니다.
- 공지와 비교과 상세는 본문 구성이 달라도 공통 타이포·버튼·팝업 스타일을 유지합니다.

## 7. 프론트만 구현된 것과 서버가 필요한 것

| 항목 | 현재 상태 | 실제 서비스 연결 작업 |
|---|---|---|
| 로그인·회원가입·카카오·구글·아이디/비밀번호 찾기 | UI/입력 검사/준비 안내 | 인증 API·콜백·본인 확인·오류 연결 |
| 내 정보·MY PICK | 브라우저 저장과 화면 동작 | 계정별 조회/저장·실패 복구·계정 전환 분리 |
| 공지/비교과 | 정적 데이터로 탐색 | 공개 수집 데이터·분류/ID 매핑·본문·이미지·페이지네이션 |
| 추천 | 학년·트랙·관심·마감 기반 로컬 규칙 | 서버 추천 계약·전체 개수·이유·미확인 조건 정책 |
| AI 비교하기 | 선택한 정보의 나란히 비교 | 실제 생성 AI를 사용할 경우 API·근거·실패/비용 처리 |
| 비밀번호 변경·탈퇴·소셜 연결 | 관리 UI·확인 안내 | 서버 처리·재인증·결과 반영 |
| 오프라인 | 연결 상태 알림 | 서비스워커/PWA 설치·캐시·오프라인 동기화는 미구현 |

**주의:** `setAccountSession`은 서버에서 인증된 결과를 화면에 전달하는 어댑터입니다. 호출만으로 로그인 게이트·서버 권한·프로필 로드가 완성되지 않습니다. 세션 확인→계정 전환 시 기존 정보 정리→해당 계정 정보 로드/주입→화면 진입을 연결해야 합니다.

## 8. 데이터 규칙을 빠르게 이해하기

1. 공지/비교과 게시물 ID는 전체에서 유일하고 안정적이어야 북마크·비교·상세가 같은 항목을 가리킵니다.
2. 학생 **관심 분야**, **공지 카테고리**, **비교과 카테고리**는 다른 분류입니다. 같은 한글 단어라도 ID를 섞지 않습니다.
3. `tracks: []`는 제한 없음, null/누락은 조건 미확인입니다. 미확인을 전 학년/트랙 무관으로 바꾸지 않습니다.
4. 현재 읽기 모델은 시작일/마감일이 필수입니다. 날짜 없는 공지를 넣으려면 모델·필터·D-day·상세를 먼저 확장합니다.
5. `replaceContentRecords`는 **전체 스냅샷 교체**입니다. 페이지네이션의 한 페이지를 그대로 넣으면 총 개수/북마크가 어긋납니다. 실패 상세는 `issues`로 반환합니다.
6. D-day는 한국 날짜 기준이며 날짜 없는 기간·정확한 시각 마감 지원은 추가 작업입니다.
7. API 비밀 키·소셜 secret·DB 정보는 프론트에 넣지 않습니다. 브라우저에서 내려받을 수 있는 파일은 공개 정보입니다.

정확한 필드 표·검증 규칙·미확정 정책은 [백엔드 전달서](backend-handoff-2026-10-16.md)를 우선합니다. 아래 점검 문서는 작업 이력이므로 오래된 권장안이 현재 코드와 다르면 최신 전달서·실제 코드를 확인합니다.

## 10. 성진님이 시작할 때 확인할 것

- 이 전달본으로 먼저 로컬 화면과 `npm run check`를 확인합니다.
- 인증 방식, API 명세/실제 JSON, 날짜 없는 공지, 안정적인 트랙 ID/분류 매핑, 계정 복구 수단을 합의합니다.
- 실제 네트워크 호출부는 새로 만들고, 기존 로컬 읽기/저장 지점에 연결합니다. 기존 `backend/`의 상태가 이 프론트 전달본만으로 완성되는 것은 아닙니다.
- 연동 뒤에는 회원가입→내 정보→추천→저장→새로고침→다른 계정 전환을 실제 브라우저/서버에서 검증합니다.
- 프론트 배포는 `dist/`를 정적 루트로 사용합니다. 다른 도메인으로 옮기면 공유 메타 태그의 절대 URL, API CORS/소셜 콜백, 캐시 버전을 함께 바꿉니다.
- GitHub에 올린 변경이 기존 ChatGPT Sites 배포로 자동 반영되지는 않습니다. 자동 배포 설정은 별도 작업입니다.
