# 로그인 및 계정별 저장 연결

최신 규칙·미확정 정책·연동 순서는 [백엔드 연동 전달서](backend-handoff-2026-10-16.md)를 우선합니다. 계정 ID 전환으로 기존 화면이 비워진 뒤 새 계정 데이터를 주입해야 합니다.

현재 `dist/login.js`는 로그인 UI입니다. 아이디·비밀번호 또는 SNS 버튼을 눌러도 인증 성공으로 처리하지 않습니다. 입력한 비밀번호는 저장하거나 전송하지 않습니다. `hsupick-browse-this-tab`은 탭의 둘러보기 상태이며 인증 정보가 아닙니다.

## 백엔드에서 전달할 정보

- 배포된 API 주소 및 API 명세
- 일반 아이디(이메일 형식 강제 없음)·비밀번호 로그인, 회원가입, 아이디/비밀번호 찾기 지원 범위
- 카카오·구글 로그인 시작 주소, 콜백 주소와 설정 방법
- 현재 로그인한 사용자 확인 및 로그아웃 방법
- 학년·1~3트랙·관심 분야 조회/수정 API
- MY PICK 북마크 조회/저장/해제 API
- 인증 쿠키, CORS, CSRF 및 오류 응답 규칙

## 프론트 연결 시 동작

1. 서버에서 세션을 확인한 뒤 로그인 화면 또는 기존 화면을 표시합니다.
2. 일반 로그인은 서버에서 검증하고, SNS 로그인은 서버가 제공하는 인증 시작 주소로 이동합니다. 제공자 비밀 키는 프론트에 넣지 않습니다.
3. 성공 확인 후 사용자 정보를 가져옵니다. 서버가 인증을 거절하거나 연결되지 않으면 로그인 완료로 표시하지 않습니다.
4. 학년·트랙·관심 분야와 MY PICK을 계정별로 조회하고 저장합니다. 인증과 데이터 접근 권한은 서버에서 검사합니다.
5. 기존 브라우저 저장값은 사용자의 선택 없이 다른 계정에 자동으로 덮어쓰지 않습니다. 이전 여부를 확인한 뒤 반영합니다.
6. 로그아웃할 때 현재 사용자의 화면 상태와 비교 선택을 비웁니다. 서버의 계정 데이터는 유지합니다.

실제 인증 연동 전까지 기존 브라우저 저장 동작이 유지됩니다. 로그인 UI 자체는 계정 간 동기화나 접근 제한을 제공하지 않습니다.

## 회원가입 화면 및 입력 규칙

`#signup`에서 이름·아이디·비밀번호·비밀번호 확인을 입력합니다. 모바일과 PC 모두 동일하게 이름을 받습니다. 입력 중 오류를 안내하며, 제출 시 첫 오류 항목으로 포커스를 이동합니다. 계정 서버가 연결되지 않은 현재는 입력 검사만 수행하고 가입 완료로 표시하지 않습니다. 비밀번호는 브라우저 저장소에 저장하지 않고 화면 이동 또는 제출 검사 통과 시 비웁니다.

- 아이디: ASCII 영문 대소문자·숫자만, 4~20자. 한글·공백·특수문자 불가. 이메일 형식 강제 없음.
- 비밀번호: ASCII 영문·숫자·특수문자를 각각 1개 이상 포함, 8~32자. 한글·공백 불가. 허용 특수문자는 ASCII `!`부터 `~` 범위의 기호입니다.
- 비밀번호 확인: 비밀번호와 완전히 일치해야 합니다. 자동 trim/변환을 하지 않습니다.

서버에서도 동일한 규칙을 검증하고 아이디 중복을 검사해야 합니다. 중복 여부는 현재 화면에서 확인하지 않습니다. 회원가입 API의 주소·요청/응답 형식·세션 처리 계약이 전달되면 실제 요청 및 가입 후 이동을 연결합니다.

전체 연동 전 점검 결과와 모바일/PC 기능 비교는 `docs/frontend-preflight.md`를 참고하세요.

## 계정 상태 UI 연결 지점 (v1.16.70)

`dist/account-session.js`는 인증 API 연결을 위한 화면 상태 어댑터입니다. 인증 권한을 부여하지 않으며, 입력한 이름이나 둘러보기 상태를 로그인으로 취급하지 않습니다.

```js
import {setAccountSession} from './account-session.js?v=1.16.73';
// 서버에서 세션을 확인하고 해당 사용자의 데이터를 가져온 후 실행합니다.
setAccountSession({
  user: {id: serverUser.id, name: serverUser.name},
  logout: async () => {
    const response = await fetch(LOGOUT_ENDPOINT, {method: 'POST', credentials: 'include'});
    if (!response.ok) throw new Error('로그아웃하지 못했어요. 다시 시도해 주세요.');
  }
});
```

`LOGOUT_ENDPOINT`는 실제 명세에 따라 설정하고 CSRF 처리도 연결해야 합니다. 로그아웃 함수는 서버 요청만 수행하며 성공 시 어댑터가 화면 세션을 비웁니다. 실패 시 로그인 상태를 유지합니다. 로그인 글자는 파란색, 로그아웃 글자는 빨간색입니다. 중복 로그아웃 요청은 합쳐서 실행합니다. 로그아웃 성공 후 화면의 프로필·북마크·비교 상태 및 현재 브라우저 저장값을 비우고 `hsu-signout` 이벤트로 로그인 화면으로 돌아갑니다. 서버의 계정 데이터는 삭제하지 않습니다. 추후 계정별 데이터 로딩이 붙기 전에는 `setAccountSession`을 호출하지 마세요.

## 첫 사용 안내

- `hsu-app-enter` 이벤트: 앱 진입이 완료된 뒤 발생시킵니다. 현재는 둘러보기 진입 시 호출합니다. 첫 방문의 기본 안내는 로그인 이전에 먼저 표시하므로 둘러보기에서 다시 열리지 않습니다. 실제 로그인 연결 후에는 서버 세션 확인과 계정별 데이터 조회가 끝난 뒤 발생시키세요.
- 내 정보 → 맞춤 추천 → MY PICK → AI 비교하기 4장. 자동 넘김 없음. 건너뛰기·이전·다음 지원.
- 안내를 완료하거나 나가면 `hsupick-onboarding-v2`로 이 브라우저에서의 확인 여부만 저장합니다. 계정별 완료 이력은 현재 제공하지 않으므로 API 연동 시 사용자별 플래그로 교체할 수 있습니다.
- 내 정보 미입력자는 마지막 버튼에서 입력 폼으로 이동합니다. 입력된 정보가 있으면 현재 화면으로 돌아갑니다. 하단 ‘한성픽 사용안내’ 안의 ‘처음 사용 안내 다시 보기’에서 다시 열 수 있습니다.
- 상세 링크 등 다른 팝업이 열려 있으면 자동 안내로 덮지 않습니다.

### 첫 진입 순서 변경 (v1.16.71)

첫 방문에는 로그인 필드를 숨기고 온보딩 4장을 먼저 표시합니다. 마지막 ‘시작하기’, 건너뛰기, Escape는 모두 로그인으로 이어집니다. 브라우저 Back도 로그인으로 돌아오며 앱 본문을 노출하지 않습니다. 이전에 안내를 확인한 방문자는 로그인 화면부터 시작합니다. 명시적인 회원가입 딥링크는 회원가입을 우선합니다. MY PAGE에서 다시 연 안내는 로그인으로 이동하지 않고 기존 화면으로 돌아갑니다. 이용 안내는 4개 기능 카드와 마감/실제 신청 안내로 구성하며, 브라우저 저장 안내 박스와 하단 로그인 링크를 삭제했습니다. 서버 저장을 완료했다고 표시하지 않습니다.

## 연동 준비 상태 — v1.16.73

최신 판정은 `docs/prelaunch-review-2026-10-16.md`를 따릅니다. 세션 어댑터 호출만으로 로그인 요청/성공 화면 진입/계정별 프로필 조회·저장까지 연결되지 않습니다. 아직 로컬 `persist()`를 서버 쓰기로 전환하고 데이터 주입 경로·오류·재시도를 연결해야 합니다. 계정 ID가 바뀌면 이전 화면 정보·초안·선택을 비우고, 만료 시 로그인 화면으로 돌아가도록 신호를 보냅니다. 게스트 데이터 이전 여부와 서버 데이터 저장은 별도 계약입니다.

로그아웃 핸들러는 서버 요청과 HTTP 실패 검사를 수행하고, 세션 정리는 어댑터가 담당합니다. 같은 계정 세션에서의 중복 요청만 합치며, 계정이 바뀐 뒤의 새 로그아웃은 별도로 처리합니다. 이전 로그인/로그아웃 요청 응답이 새 계정을 덮어쓰지 않도록 실제 로그인·프로필 요청에도 요청 순서 검사가 필요합니다.
