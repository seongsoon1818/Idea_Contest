# 모바일 개선 및 서버 연결 범위

## 구현된 화면

- 모바일 상세 하단: MY PICK 저장/해제, 뒤로가기. PC 상세 버튼은 기존 구성 유지.
- 모바일 뒤로가기: 목록 상태·스크롤 복구, 상세/이미지 확대/내 정보 단계/트랙 팝업 이동을 History 상태에 기록. 비밀번호는 방문 기록에 저장하지 않음.
- 단계별 정보 입력: 이름 → 학년 선택 후 트랙 노출 → 1학년은 1트랙만 필수, 2학년 이상·기타는 1·2트랙 필수/3트랙 선택 → 관심 분야.
- 트랙: 검색은 즉시 결과, 분류는 대학 → 학부·학과 → 선택 항목. 1학년 1트랙에서 대학 자체 선택 가능.
- MY PAGE: 내 정보·로그인 관리·추천 정보 다시 설정·회원 탈퇴.
- 미니 MY: 이름 마지막 두 글자(이지원 → 지원), 정보 수정 및 로그인 진입. 실제 인증 세션이 없으므로 로그아웃 완료나 연결된 소셜 계정으로 표시하지 않음.
- 추천 정보 다시 설정은 기존 MY PICK을 유지. 실제 정보는 최종 입력 완료 시 변경.

## 계정 API 연결 전 상태

현재 서비스에는 계정 서버 연결이 없습니다. 회원가입·로그인·카카오/구글 연결·비밀번호 변경·탈퇴를 화면 조작만으로 성공 처리하지 않습니다. 비밀번호 변경 폼은 현재/새 비밀번호·확인을 검사한 후 연결 전 안내를 표시하며, 검사 통과 시 입력한 비밀번호를 비웁니다. 이름·추천 정보·MY PICK의 기존 로컬 보관은 서버 연결 전까지 유지됩니다.

`auth-integration.md`에 필요한 로그인/세션 API 조건이 정리되어 있습니다. 추가 계약:

- 사용자 정보의 `name`(공백 제거 후 1~30자), 학년·트랙·관심 분야. 로그인 성공 후 프로필을 로드해 표시 이름 갱신.
- 로그인 수단 조회: 일반 계정 여부, 연결된 Kakao/Google 정보. 서버 확인 전에는 연결 상태를 추정하지 않음.
- 소셜 계정 연결/해제는 로그인한 계정의 세션을 검사. 남은 로그인 수단이 없는 해제는 차단.
- 비밀번호 변경: 현재 비밀번호 재검증 및 새 비밀번호 규칙 검증. 소셜 전용 계정에서는 비밀번호 메뉴 숨김.
- 로그아웃은 서버 세션 폐기 후 사용자 화면과 개인정보 상태를 비우고 로그인 화면으로 이동. MY PICK의 서버 데이터는 보존.
- 회원 탈퇴는 별도의 확인/재인증 및 서버 삭제 완료 후 처리. 실패 시 계정 데이터나 MY PICK을 로컬에서 먼저 지우지 않음.

## 공지 이미지 응답 형식

공지/프로그램 객체에 원문 순서의 `images` 배열을 전달합니다.

```json
{
  "images": [
    {"url": "https://your-image-host.example/notice-1.png", "alt": "행사 모집 안내 포스터"}
  ]
}
```

문자열 URL 배열도 지원합니다. 외부 이미지는 절대 HTTPS URL이어야 하고 로그인 쿠키 없이 열려야 합니다. 서버 이미지 응답의 접근 정책이나 원본 핫링크 차단이 있으면 서버 저장소/프록시 주소가 필요합니다.

모바일 상세에서 전체 이미지 비율로 표시 → 누르면 확대 → 이미지 원본을 새 창으로 열기. 실패하면 원문 확인 안내를 표시합니다. 현재 내장 데이터에는 실제 공지 이미지 URL이 없으므로 서버가 배열을 전달해야 실제 포스터가 나타납니다. 이미지 인식·OCR·AI 요약은 이번 구현에 포함하지 않습니다.

## 확인 범위

DOM 흐름 검사에서 PC 기존 기능, 모바일 단계 이동·뒤로/앞으로 가기·필터/스크롤 복구·추천 정보 재설정 시 북마크 유지·이미지 오류 처리를 확인합니다. 실제 iPhone 16 브라우저의 화면 배치와 원격 이미지 서버 응답은 별도 브라우저 검수가 필요합니다.
