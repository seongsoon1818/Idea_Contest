## 동작과 운영 설정

- 기본 공개 데모에서는 실제 계정 API가 비활성화되어 있습니다. `localhost`, `127.0.0.1`, `[::1]`에서는 활성화됩니다.
- 운영에서 `/api/v1`이 실제 API로 연결되는 것을 확인한 다음 HTML의 `<head>`에 `<meta name="hsupick-account-api" content="enabled">`를 넣어 활성화합니다. API 연결 없이 이 설정부터 켜면 접속 시 재연결 화면이 표시될 수 있습니다.
- 쓰기 요청에 `X-CSRF-Guard: 1`을 보내며, 액세스 토큰은 프론트 메모리에서 관리합니다. 갱신 토큰은 서버의 HttpOnly 쿠키를 사용합니다. 비밀번호나 토큰을 브라우저 저장소에 저장하지 않습니다.
- 동일 출처 탭에서는 Web Locks로 쿠키를 바꾸는 요청을 직렬화합니다. 잠금을 쓸 수 없으면 갱신 API의 `401 INVALID_REFRESH_TOKEN`에만 최대 세 번 재시도합니다.
- 오프라인·시간 초과·서버 장애·알 수 없는 오류는 로그인 만료로 간주하지 않고 현재 주소에서 다시 연결하기를 제공합니다. `401 INVALID_REFRESH_TOKEN` 또는 `401 SESSION_REVOKED`면 로그인 흐름으로 돌아가며, `403 ACCOUNT_DISABLED`면 서버 안내를 표시합니다.

## 검증 결과와 남은 확인

- 이번 전달 코드에서 `cd frontend && npm run check`를 실행합니다. 화면 동작 단언 988개를 포함하는 회귀 검사를 사용하며 계정 화면 검사는 모의 API입니다.
- 앞선 작업에서는 실제 MySQL 테스트 DB에 프론트 클라이언트 두 개를 연결해 갱신 직렬화, 충돌 이후 재시도, 만료·로그아웃 이후 복원 거부를 확인했습니다. 이번 GitHub 전달 자체를 운영 DB 검증으로 해석하지 않습니다.
- 운영 또는 스테이징 브라우저에서 가입 → 로그아웃 → 로그인 → 새로고침 → 두 탭 동시 새로고침 → 네트워크 실패 → 다시 연결하기를 직접 확인해야 합니다.
- 공지·비교과·추천·MY PICK·AI 비교·알림 화면의 실제 서버 연동은 이 패키지의 완료 범위에 포함되지 않습니다. 서버 검색 수정과 알림 데이터 형식 통일도 별도 작업입니다.
- 한 탭의 로그아웃을 다른 탭 화면에 즉시 반영하는 기능, 제안한 이름 문자 제한은 이번 변경에 포함되지 않습니다.

## 합치기 전 확인

1. 변경 파일이 모두 `frontend/` 아래인지 확인합니다.
2. `frontend/`에서 `npm run check`를 실행합니다.
3. `docs/local-auth-integration.md`의 절차로 로컬 API와 연결합니다.
4. 운영 프록시·허용 출처·쿠키 설정을 확인한 후에만 계정 API를 활성화합니다.

이 패키지는 프론트 소스 전달입니다. 팀 저장소 `main` 병합과 운영 서버 배포, 운영 DB 연결은 별도 단계입니다.

## 패치 적용 예시

최신 `main`이 확인 당시 기준인 `a6e3c7e`이고 작업 중인 변경이 없는 로컬 저장소에서 실행합니다. 다른 사람이 프론트를 수정했다면 바로 덮어쓰지 말고 변경 내용을 먼저 대조하세요.

```sh
git switch -c frontend/fix/account-session-handoff
git apply --check /path/to/HSU-PICK-frontend-update.patch
git apply /path/to/HSU-PICK-frontend-update.patch
cd frontend
npm run check
```

ZIP은 `frontend/` 전체를 담고 있으며 저장소 루트에서 같은 폴더 구조로 풀어 사용할 수 있습니다. **ZIP과 패치 중 한 가지 방법만** 사용합니다. 프론트 검토 후 생성·변경된 파일만 커밋해 원격 브랜치로 push하고 PR을 만들면 됩니다. 백엔드 파일은 패키지에 포함하지 않았습니다.
