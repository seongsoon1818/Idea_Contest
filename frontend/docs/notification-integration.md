# 알림 연동 — 2026-10-28 / 프론트 v1.17.0

## 구현된 범위
- PC/모바일 공통 상단 종 아이콘 → `#notifications` 알림함. 미읽음 빨간 점, 최신순, 개별 읽음/모두 읽음.
- 마감 항목 → 공지 상세. 삭제된 공지는 안내. 맞춤 항목 → 추천 목록.
- MY PAGE의 마감/맞춤 독립 스위치. 푸시 수신 켜기/끄기는 현재 브라우저 단위.
- `notification-sw.js`: Web Push 수신/시스템 알림, 동일 ID tag, 클릭하여 기존 창/새 창 열기.
- 서버 미연결 상태에서는 계정별 브라우저 저장과 화면이 열린 동안의 정책 평가만 동작. 실제 로그인이나 서버 저장/예약 푸시 완료를 가장하지 않음. 첫 목록은 맞춤 알림으로 소급 발송하지 않음.
- 알림 목록은 현재 최대 200건 표시. 실제 보관 기간은 서버 정책과 합의 필요.

## 백엔드 연결이 필요한 부분
현재 사이트는 정적 HTML/JS이며 예약 작업/알림 DB/푸시 발송 서버가 없습니다.
성진님 서버가 인증, 원문 수집, 신규 추천 판단, 일별 예약, 알림 저장, 푸시 발송을 담당합니다.
프론트의 로컬 평가를 배경 발송에 사용하면 안 됩니다. 연결 후에는 서버 결과만 사용합니다.

1. 서버 로그인 확인 후 기존 `setAccountSession({user:{id,name},logout})` 연결.
2. `window.HSUPickNotifications.connect(adapter)` 호출. 사용자/세션이 바뀔 때마다 재연결.
3. 프로필/저장 PICK/신규 공지 데이터와 알림 설정을 서버 사용자 ID에 연결.
4. 사이트를 닫은 상태, 휴대폰 잠금 상태에서 실제 수신 확인. 플랫폼별 권한/홈 화면 설치 요구는 배포 환경에서 별도 검증.

## 프론트 어댑터 인터페이스
메서드들은 실제 인증 API를 호출해야 하며, 프론트에 사용자 ID를 보냈다는 이유만으로 접근을 허용하면 안 됩니다.
토큰은 URL이나 localStorage 설정에 넣지 마세요. 기존 인증 방식으로 처리하세요.

```js
await window.HSUPickNotifications.connect({
  // 조회 API의 페이지네이션은 어댑터에서 처리. 최신순 최대 200건 전달.
  load: async () => ({
    settings: { deadline: true, recommendation: true },
    notifications: [{
      id: '서버에서 생성한 고유 ID',
      type: 'deadline', // 또는 'recommendation'
      itemId: '공지 ID', // deadline 필수. recommendation은 null
      title: '저장한 PICK이 내일 마감돼요!',
      body: '공지 제목',
      createdAt: '2026-10-28T00:00:00Z',
      read: false
    }]
  }),
  updateSettings: async ({deadline,recommendation}) => { /* 서버 저장 완료까지 await */ },
  markRead: async (ids) => { /* 본인 알림인지 확인 후 읽음 저장, 멱등 */ },
  vapidPublicKey: '서버 VAPID 공개키', // 비밀키는 서버에만 저장
  subscribePush: async (subscription) => { /* 구독 정보를 현재 로그인 계정에 저장 */ },
  unsubscribePush: async (subscription) => { /* 이 브라우저의 현재 사용자 구독 해제 */ },
  isPushSubscribed: async (subscription) => { /* 현재 계정에 활성 연결된 구독인지 boolean 반환 */ }
});
```

`load`, `updateSettings`, `markRead`는 필수입니다. 푸시 관련 메서드/공개키가 없으면 푸시 켜기는 실제로 완료되지 않습니다.
`PushSubscription.toJSON()`에는 endpoint, keys.p256dh, keys.auth가 포함됩니다. 개인별 구독 자료로 취급하세요.
설정 저장 실패 시 UI는 이전 값으로 돌아갑니다. 세션이 바뀐 뒤 도착한 이전 사용자의 조회 결과는 적용하지 않습니다.

## 발송 규칙 (서버에서 보장)
| 종류 | 생성 조건 | 중복 키 | 이동 |
|---|---|---|---|
| 마감 | MY PICK 저장, 신청 마감일 확정, 접수 중, 한국 시간 기준 마감 전날 오전 9시 | userId + type + noticeId | `#notice/{encodeURIComponent(itemId)}` |
| 맞춤 | 마지막 처리 이후 새로 수집된 소식 중 현재 학년/트랙/관심 기준에 맞고 모집 중인 소식. 오전 9시 한 번으로 묶음 | userId + type + Asia/Seoul 날짜 | `#recommend` |

- 반복 수집/작업 재시도/여러 기기에서도 DB 고유 제약 및 트랜잭션으로 알림 1건만 생성.
- 알림함 1건 생성 후, 푸시 허용된 구독에 같은 id로 전달. 푸시 실패가 알림함 생성을 취소하거나 같은 알림을 재생성하면 안 됨.
- 마감 당일에는 전날 알림을 재발송하지 않음. 발송 직전에 저장 취소, 신청 마감/기간 변경/조기 종료, 설정 OFF 여부 재확인.
- 날짜 미기재/해석 불가를 임의 날짜로 보완하지 않음. 날짜만 있고 시각이 없으면 확정된 마감 시각으로 변환하지 않음.
- 최초 가입/설정 ON/프로필 변경을 신규 공지 등록으로 간주하여 기존 공지를 대량 발송하지 않음.
- 맞춤 신규 항목이 0건이면 생성/푸시 모두 하지 않음. 9시 이후 수집분은 다음 묶음에서 발송 전 재검증.
- 마감/맞춤 스위치 OFF는 해당 종류의 신규 알림함 생성과 푸시 모두 중단. 기존 알림 기록은 유지.
- 브라우저 푸시 OFF 또는 권한 거절은 푸시만 중단. 켜둔 종류의 알림함은 계속 생성.
- 예약 마감일 연장 시 이미 발송한 공지를 다시 알릴지는 이번 범위에서는 '재발송 없음'.

## 푸시 데이터와 보안
Push payload는 위 알림 JSON과 같은 `id/type/itemId/title/body`를 사용합니다.
worker는 외부 URL을 payload로 받지 않고 내부 상세/추천 경로를 직접 구성합니다.
푸시 클릭 시 `?notification={id}`를 포함해 열고 로그인 후 알림 API가 연결되면 읽음 처리합니다.
서버는 로그아웃/회원 탈퇴 시 해당 기기 구독과 계정의 연결을 해제해야 합니다.
공용 기기 계정 전환 시 구독 endpoint를 이전 사용자와 동시에 연결하지 마세요.
로그아웃 API 처리, 작업자 전송 직전 사용자-구독 관계 재검증, 404/410 구독 정리를 구현하세요.
서비스 워커와 VAPID만으로 예약 발송은 되지 않습니다. 비밀키와 정기 작업은 서버에 필요합니다.

## 인수 검증
- 전날 08:59/09:00, 마감 당일, 한국/해외 기기 시간대, 마감일 변경/삭제.
- 저장 취소/설정 OFF 직후의 작업 실행, 신규 없음, 같은 날 여러 수집·여러 작업자, 다음날 묶음.
- 두 종류 독립 설정, 권한 거절/미지원, 푸시 OFF 후 알림함 생성.
- 알림 클릭 → 상세/추천, 로그인 후 복귀, 삭제된 공지, 읽음 상태 새로고침 유지.
- 계정 A → 로그아웃 → B에서 A의 기록/푸시 노출 금지. 여러 기기 읽음 동기화.

자동 검증: `npm run check` (정책/서비스 워커/모바일·PC DOM 흐름 포함).
