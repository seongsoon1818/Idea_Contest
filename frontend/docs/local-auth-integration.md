# 로컬 계정 API 연동

이번 변경 범위: 회원가입, 일반 로그인, 새로고침 후 세션 복원, 로그아웃.
공지·비교과·MY PICK은 기존 데모 데이터로 동작한다. 운영 DB나 배포 설정은 변경하지 않았다.

## 로컬 실행

1. 별도의 로컬 MySQL 테스트 DB를 만든다. 운영 DB 주소는 사용하지 않는다.
2. `backend/.env.example`을 `backend/.env`에 복사하고, 테스트 DB 주소와 테스트용 JWT 비밀값을 설정한다. `ALLOWED_ORIGINS=http://127.0.0.1:8080`, `PORT=3000`으로 맞춘다.
3. `backend/`에서 실행한다.

   ```sh
   pnpm install --frozen-lockfile --ignore-scripts
   pnpm run build
   pnpm run prisma:deploy
   pnpm run catalog:seed
   pnpm start
   ```

4. 별도 터미널에서 저장소 루트 기준 `node frontend/scripts/local-auth-preview.mjs`를 실행한다.
5. 브라우저에서 `http://127.0.0.1:8080`을 연다. 가입 → 로그아웃 → 로그인 → 새로고침 → 로그아웃 순서로 확인한다. 이미 가입한 아이디로 다시 가입할 때 오류가 표시되는지도 확인한다.

로컬 프록시는 화면과 API를 같은 주소로 제공한다. API 요청은 `127.0.0.1:3000`으로 전달된다. 프론트는 `X-CSRF-Guard: 1`을 보내고, 브라우저는 서버의 HttpOnly 갱신 쿠키를 관리한다. 비밀번호와 토큰을 브라우저 저장소에 기록하지 않는다.

두 탭에서 새로고침하면 프론트가 Web Locks로 계정 쿠키를 바꾸는 요청을 순서대로 처리한다. 잠금을 쓸 수 없는 환경에서는 갱신 API의 `401 INVALID_REFRESH_TOKEN`에만 짧은 간격으로 최대 세 번 다시 시도한다. 브라우저에서 확인할 때는 로그인한 상태로 같은 주소를 두 탭에 열고 동시에 새로고침한다. 두 탭 모두 로그인 상태가 유지되어야 하며, 로그아웃으로 세션을 끝낸 뒤 다른 탭을 새로고침하면 로그인 화면이 표시되어야 한다.

시작할 때 로그인 상태를 확인하는 중 오프라인, 요청 시간 초과, 서버 장애가 발생하면 현재 주소에서 `다시 연결하기`를 표시한다. 로컬에서 로그인한 다음 개발자 도구로 네트워크를 오프라인으로 바꾸고 새로고침해 확인할 수 있다. 온라인으로 되돌린 후 `다시 연결하기`를 누르면 로그인 입력 없이 기존 화면이 열려야 한다. 백엔드가 세션 만료 또는 해제를 확인하면 일반 로그인 흐름으로 돌아간다.

## 배포 시

같은 도메인에서 화면을 제공하고 `/api/v1/`을 백엔드로 전달한다. 해당 배포 주소를 백엔드의 허용 출처에 추가하고, 배포용 HTML의 head에 `<meta name="hsupick-account-api" content="enabled">`를 넣는다. 데모 HTML은 기본적으로 외부 도메인에서 실계정 요청을 보내지 않는다.

`cd frontend && npm run check`는 실제 UI 코드와 모의 API 응답을 검증한다. 실제 DB를 사용하는 통합 확인은 위 로컬 절차로 별도 수행한다.
