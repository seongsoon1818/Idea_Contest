# 실제 사용 및 백엔드 연결 준비 점검 — 2026-10-16

## 결론

**현재는 화면 체험이 가능한 프론트 프로토타입이며, 실제 학생 대상 정식 서비스 출시는 보류해야 합니다.**

화면 탐색·정보 입력·로컬 저장·조건 비교 흐름은 검사했지만, 실제 계정 인증·계정별 서버 저장·학교 데이터 API가 연결되지 않았습니다. ‘프론트에서 에러가 안 남’과 ‘실제 서비스가 정상 동작함’은 구분해야 합니다. 백엔드 주소만 바꾸면 끝나는 구조도 아닙니다.

## 1. 사용자가 지금 이용할 수 있는 범위

| 기능 | 현재 상태 | 실제 사용 판단 |
|---|---|---|
| 첫 진입 온보딩·건너뛰기·다시 보기 | 구현·검사 | 화면 체험 가능 |
| 일반 로그인·회원가입 | 입력 규칙 검사만 수행 | 실제 계정 생성·인증 불가 |
| 카카오·구글 로그인/연결 | 버튼·안내만 구현 | 제공자 인증 및 연결 불가 |
| 아이디·비밀번호 찾기·변경·탈퇴 | 화면/입력 검사·미연결 안내 | 실제 계정 변경 불가 |
| 학년·트랙·관심 분야 입력 | 1학년 1트랙, 그 외 1·2 필수/3 선택 | 이 브라우저에서만 체험 가능 |
| 공지·프로그램 탐색 | 정적 데이터 모듈 사용 | 실제 모집 정보로 서비스하면 안 됨 |
| 조건 기반 추천 | 학년·트랙·관심·모집 상태 기준 | 로컬 조건 매칭 가능, 서버 추천 연결 필요 |
| 북마크·MY PICK | 브라우저 저장 | 계정/기기 간 보관을 보장하지 않음 |
| AI 비교하기 | 최대 3개 정보 대조 화면 | 실제 AI 분석 요청은 미연결 |
| 공지 이미지 | HTTPS URL 표출·확대·실패 안내 | 실제 이미지 URL 전달 및 외부 사이트 허용 여부 확인 필요 |
| 원문 이동 | 개별 원문 URL이 없으면 학교 목록/포털로 이동 | 실제 게시물/프로그램 URL 필요 |
| 모집 상태·D-day | 한국 시간 날짜 기준 | 시·분 단위 마감은 아직 지원하지 않음 |
| 오프라인 | 이미 열린 화면의 로컬 조작 | 최초 오프라인 접속/서버 저장 불가 |

로그인 없이 둘러보기와 로그인 화면의 뒤로가기 둘러보기 경로는 현재 체험을 위한 경로입니다. 로그인 필수 서비스로 출시할 때는 정상 서버 세션 확인 및 인증 만료 처리와 함께 이 경로를 정리해야 합니다. 프론트 화면 제한만으로 API 접근 권한을 보장할 수는 없습니다.

현재 `setAccountSession`은 UI 상태 어댑터입니다. 이것만 호출한다고 인증 요청·서버 프로필 주입·서버 저장이 연결되지는 않습니다. 계정이 바뀌면 기존 화면 상태를 비우지만, 새 계정의 실제 데이터를 불러오고 저장하는 작업은 별도로 연결해야 합니다. `persist()`와 저장 버튼 흐름도 아직 로컬 저장이므로, 서버 성공과 동일하게 취급하면 안 됩니다.

## 4. 추가한 목록 입력 경계

`dist/content-contract.js`의 `normalizeContentRecords`와 `replaceContentRecords`는 **네트워크 요청을 하지 않는 읽기 모델 검증 도구**입니다. 실제 API 응답 객체의 어느 필드에 목록이 들어 있는지는 명세에 따라 호출부에서 매핑해야 합니다.

```js
import {replaceContentRecords} from './content-contract.js?v=1.16.73';
// HTTP 상태·인증·현재 요청 순서·응답 구조를 확인한 뒤 호출합니다.
const result = replaceContentRecords(mappedRecords);
if (!result.ok) {
  // 기존 목록은 유지됩니다. 실제 호출부에서 오류/재시도 UI를 연결해야 합니다.
  // result.issues: [{index, field, message}]
}
```

| 필드 | 이 경계가 기대하는 값 |
|---|---|
| `id` | 문자열 또는 0 이상의 안전한 정수. notice/program 전체에서 중복 없는 ID. 영문·숫자·밑줄·하이픈, 1~128자 |
| `type` | `notice` / `program` |
| `title` | 비어 있지 않은 문자열 |
| `start`, `deadline` | 실제 달력에 존재하는 `YYYY-MM-DD`, 시작일≤마감일. 현재 이 경계는 날짜 단위 모델 |
| `publishedAt` | 실제 게시 등록일 또는 ISO 타임스탬프. 미확인 시 빈 값으로 유지 |
| `grades` | 1~4 숫자/숫자 문자열 배열. 누락·null은 대상 미확인 |
| `tracks` | 대상 트랙 문자열 배열. 명시적 `[]`는 제한 없음, 누락·null은 미확인 |
| `category` | 관심 주제 ID. 불일치 시 임의 추정하지 않음 |
| `noticeCategory`, `programCategory` | 각각 UI 분류 ID. 미확인 시 미분류 |
| `subtitle`, `benefit`, `department` | 선택 문자열. 미확인 값은 원문 확인으로 표시 |
| `eventAt` | 선택 날짜. 잘못된 값은 확정 일정처럼 표시하지 않음 |
| `preparations`, `tags` | 선택 문자열 배열 |
| `publicInfo` | 비교과 공개 메타데이터 객체. 없는 항목을 풍부한 다른 데이터로 채우지 않음 |
| `images` | 선택 HTTPS URL 배열 또는 `{url,alt}` 배열 |
| `originalUrl` | 실제 게시물/프로그램 원문 URL. 현재 학교 도메인 허용 규칙 적용 |

`category`와 공지/비교과의 화면 분류는 서로 다른 값입니다. 숫자 enum이나 학교의 한글 분류명을 그대로 넣으면 동일하게 동작한다고 가정하면 안 됩니다. UI 분류 ID와의 매핑표가 필요합니다.

읽기 모델 갱신은 현재 목록 전체 교체입니다. 페이지 응답 한 장씩을 무조건 전체 교체하거나, 응답이 늦게 도착한 이전 검색 결과를 다시 넣으면 안 됩니다. 요청 취소/순서 관리·서버 데이터의 계정 소유권 검사는 실제 API 호출부 책임입니다. 이 유틸리티는 서버 검증과 인증을 대체하지 않습니다.

## 5. 검증 근거 및 한계

- `npm run check` 통과: **885개 인메모리 DOM 흐름 검사**, 데이터 경계·인증 입력 규칙·이미지 URL·추천·계정 세션 검사.
- 숫자/하이픈 ID, 비어 있는 목록, 누락 메타데이터, 잘못된 날짜/ID/배열, 응답 거절 후 이전 목록 유지, 비교 대상 삭제, 트랙명 표기, 등록순, 개인정보 초기화 후 기록 복원을 검사했습니다.
- 모바일/PC 상태 분기 및 새 계정/만료된 UI 세션을 검사했습니다. 이는 실제 서버에 로그인한 검사가 아닙니다.
- 지원되는 브라우저 제어 환경이 없어 실제 iPhone/안드로이드/PC 렌더링·가상 키보드·터치·CORS/쿠키·실제 연결 차단·느린 네트워크 HTTP 응답을 확인하지 못했습니다.
- API 주소·서버 응답·실제 세션이 제공되지 않아 400/401/403/409/429/500 응답, 서버 저장 실패, 중복 제출, 토큰 만료, 제공자 콜백은 **미검증**입니다. 현재 화면 검사가 이 부분의 정상 동작을 증명하지 않습니다.

## 6. 다음 실제 연동 순서

1. API 명세와 실제 JSON 예시, 배포 주소, 로그인 세션 규칙을 받습니다.
2. 현재 사용자 조회 → 계정별 프로필/북마크 로딩 → 목록 로딩 순서를 정하고 게스트 데이터 이전 정책을 결정합니다.
3. 읽기 응답을 매핑·검증하고, 저장/해제/수정은 서버 응답 성공 뒤 완료 표시하도록 바꿉니다.
4. 정상·빈 결과·권한 없음·로그인 만료·중복·요청 제한·서버 오류·연결 끊김을 실제 API로 검증합니다.
5. 모바일/PC 실기기에서 인증부터 원문 이동·저장·재접속까지 통과한 뒤 실제 학생에게 공개합니다.
