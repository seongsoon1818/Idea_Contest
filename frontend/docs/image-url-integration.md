# 공지 이미지 URL 연동

프론트 v1.16.76 · 2026-10-16

## 합의한 흐름

서버가 원문에서 이미지 주소를 추출 → DB에는 주소/대체 설명/순서를 저장 → API 응답으로 전달 → 프론트의 `<img src="전달받은 주소">`로 표시합니다. 프론트로 이미지 바이너리나 base64를 전달할 필요가 없습니다.

현재 실제 게시물 API는 아직 연결되지 않았습니다. 이 문서는 연결할 데이터 형식과 이미 구현한 표시 동작을 정의합니다.

## 권장 응답 필드

게시물 객체에 다음 필드를 포함합니다. 아래는 전체 게시물 응답이 아닌 **이미지 필드만의 예시**입니다. 주소는 예시이므로 실제 원문 이미지의 절대 HTTPS 주소로 교체합니다.

```json
{
  "images": [
    {"url": "https://www.hansung.ac.kr/path/to/poster.jpg", "alt": "프로그램 모집 포스터"},
    {"url": "https://www.hansung.ac.kr/path/to/schedule.png", "alt": "신청 일정 안내"}
  ]
}
```

간단히 주소만 보내도 됩니다.

```json
{"images": ["https://www.hansung.ac.kr/path/to/poster.jpg"]}
```

기존 DB/API가 `imageUrls` 배열이나 단일 `imageUrl`을 쓰는 경우에도 지원합니다. 서버와 필드명을 합의한 후에는 한 형식으로 통일하는 것을 권장합니다.

| 우선순위 | 받는 필드 | 처리 |
|---|---|---|
| 1 | `images: [{url,alt}]` 또는 `images: string[]` | 원문 순서로 표시. `[]`면 이미지 없는 게시물로 처리 |
| 2 | `imageUrls: string[]` | images 배열이 없을 때 사용 |
| 3 | `imageUrl: string` | 위 배열들이 없을 때 한 장 표시 |

명시적인 `images: []`가 있으면 다른 필드에 남아 있는 주소를 다시 보여주지 않습니다. 같은 주소는 중복 표시하지 않습니다. 상대 주소는 서버에서 원문 주소를 기준으로 절대 주소로 바꾸어 전달합니다. HTTP, data:, javascript:, 계정정보가 포함된 URL은 표시하지 않습니다.

## 프론트 표시

- 공지 상세: 짧은 소개 다음에 이미지를 표시하여 이미지뿐인 공지도 확인할 수 있게 합니다.
- PC의 공지 내용 보기: 동일한 이미지 영역을 표시합니다. 비교과 상세에 이미지가 전달된 경우에도 표시합니다.
- 모바일/PC 모두 카드 너비에 맞게 이미지 비율을 유지합니다. 이미지 클릭 시 확대 화면과 이미지 원본 열기를 제공합니다.
- 이미지 없음: 빈 이미지 박스나 깨진 자리표시자를 만들지 않습니다.
- 로딩 실패/외부 표출 차단: 실패 안내와 기존 공식 사이트 이동 경로를 유지합니다.
- alt가 없으면 게시물 제목과 이미지 순서로 대체 설명을 만듭니다.
- 이미 열린 게시물의 URL이 갱신되면 새 URL로 바꾸며, 보고 있던 이미지가 삭제되면 상세로 돌아갑니다.

## 연결 위치

1. API를 호출하는 코드에서 실제 게시물 응답을 읽기 모델로 매핑합니다. 현재 네트워크 호출부는 미구현입니다.
2. 매핑 과정에서 이미지 필드도 전달해야 합니다. 제목/날짜 등만 뽑고 이미지 필드를 버리지 않습니다.
3. `content-contract.js`의 `normalizeContentRecords`/`replaceContentRecords`가 URL을 `images`로 정리합니다. 이 함수는 전체 목록 스냅샷용이며 개별 상세/페이지 단위 API는 별도 연결이 필요합니다.
4. `notice-images.js`가 주소를 정리하고 `app.js`의 `imageGallery`/`imageViewer`가 표시합니다. 수집 HTML을 innerHTML로 넣지 않습니다.

원문 서버의 로그인·외부 사용 차단·만료 주소는 프론트 코드만으로 해결할 수 없습니다. 그런 이미지에 한해 백엔드에서 안정적인 이미지 주소 또는 허용된 프록시를 제공해야 합니다. 단순 `<img>` 표출에는 일반적으로 fetch용 CORS 허용이 필요하지 않지만, 원본 서버의 응답 정책에 따라 외부 표출이 막힐 수 있습니다.

이미지 표시와 AI 이미지 인식/OCR 요약은 별개입니다. 이 작업은 URL 기반 표시만 구현하며 이미지 내용을 읽어 요약하지 않습니다.

## 확인한 범위

URL 단일/배열/객체 배열, 우선순위·중복 제거·잘못된 주소, 읽기 모델 통과, 모바일/PC DOM 상세·공지 내용 표시·갱신·삭제·실패 안내를 자동 검사합니다. 전체 검사 통과: 926개 DOM 흐름 검사와 개별 데이터/입력/세션/이미지/추천 검사. 실제 학교 이미지의 외부 접근과 실서버 응답은 연동 뒤 별도 확인해야 합니다.
